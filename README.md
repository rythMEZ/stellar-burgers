# Stellar Burgers

Клиентское SPA космической бургерной: сборка бургера из ингредиентов, оформление заказа, общая лента заказов, личный кабинет с историей заказов и авторизация.

Реализованы клиентская архитектура приложения, маршрутизация, глобальное состояние на Redux, авторизация с защищёнными маршрутами и автоматизированные тесты пользовательских сценариев.

## Стек технологий

- **React 18 + TypeScript** — UI и типизация.
- **Redux Toolkit + React Redux** — глобальное состояние, асинхронные запросы через `createAsyncThunk`.
- **React Router v6** — маршрутизация, защищённые маршруты и модальные окна поверх страниц.
- **Webpack 5 + webpack-dev-server** — сборка и dev-сервер с hot reload.
- **Storybook 7** — документация и изолированный просмотр UI-компонентов.
- **Jest + ts-jest** — юнит-тесты редьюсеров.
- **Playwright** — интеграционные (e2e) тесты пользовательских сценариев с моками сети через HAR.
- **ESLint + Prettier** — единый стиль кода.

## Функциональность

- Конструктор бургера: выбор булки, добавление, удаление и перестановка начинок и соусов, подсчёт стоимости.
- Оформление заказа: доступно авторизованному пользователю, после успеха конструктор очищается, а номер заказа показывается в модальном окне.
- Лента заказов: список всех заказов, счётчики «всего» и «за сегодня».
- История заказов пользователя в личном кабинете.
- Детальные данные ингредиента и заказа — отдельной страницей или модальным окном поверх текущего экрана.
- Авторизация: регистрация, вход, выход, восстановление и смена пароля, редактирование профиля.

## Быстрый старт

### 1. Установка зависимостей

```bash
npm install
```

### 2. Настройка окружения

В корне проекта создайте файл `.env` и укажите адрес API:

```
BURGER_API_URL=https://norma.education-services.ru/api
```

Переменная подставляется в сборку через `dotenv-webpack` и используется в запросах к серверу (`src/utils/burger-api.ts`).

### 3. Запуск проекта

```bash
npm start
```

Приложение откроется на [http://localhost:4000](http://localhost:4000).

## Архитектура проекта

Проект разделён на слои: страницы маршрутов, контейнеры с логикой, презентационные `ui`-компоненты и сервисный слой с Redux.

```
src/
├── components/          # компоненты: контейнеры и презентационный слой ui/
│   ├── app/             # корневой компонент: роутинг и модальные маршруты
│   ├── protected-route/ # защита маршрутов по статусу авторизации
│   ├── ui/              # презентационные компоненты без бизнес-логики
│   └── ...              # burger-constructor, burger-ingredients, order-info и др.
├── pages/               # страницы, привязанные к маршрутам
├── services/            # глобальное состояние
│   ├── store.ts         # configureStore и типизированные хуки
│   ├── selectors.ts     # селекторы ингредиентов (булки, начинки, соусы)
│   └── slices/          # слайсы и юнит-тесты в __tests__/
├── stories/             # Storybook-истории UI-компонентов
├── utils/               # burger-api.ts, cookie.ts, types.ts
└── index.tsx            # точка входа: BrowserRouter + Redux Provider
tests/                   # интеграционные тесты Playwright и HAR-моки (tests/hars)
```

В проекте настроены алиасы путей (в `webpack.config.js`, `tsconfig.json` и `.storybook/main.ts`):

| Алиас          | Путь                      |
| -------------- | ------------------------- |
| `@pages`       | `src/pages`               |
| `@components`  | `src/components`          |
| `@ui`          | `src/components/ui`       |
| `@ui-pages`    | `src/components/ui/pages` |
| `@slices`      | `src/services/slices`     |
| `@selectors`   | `src/services/selectors`  |
| `@api`         | `src/utils/burger-api.ts` |
| `@utils-types` | `src/utils/types`         |

## Маршрутизация

Роутинг построен на React Router v6 в компоненте `src/components/app/app.tsx`.

| Маршрут                   | Страница              | Доступ                  |
| ------------------------- | --------------------- | ----------------------- |
| `/`                       | Конструктор бургера   | всем                    |
| `/feed`                   | Лента заказов         | всем                    |
| `/feed/:number`           | Информация о заказе   | всем                    |
| `/ingredients/:id`        | Детали ингредиента    | всем                    |
| `/login`                  | Вход                  | только неавторизованным |
| `/register`               | Регистрация           | только неавторизованным |
| `/forgot-password`        | Восстановление пароля | только неавторизованным |
| `/reset-password`         | Смена пароля          | только неавторизованным |
| `/profile`                | Профиль пользователя  | только авторизованным   |
| `/profile/orders`         | История заказов       | только авторизованным   |
| `/profile/orders/:number` | Информация о заказе   | только авторизованным   |
| `*`                       | Страница 404          | всем                    |

### Модальные маршруты

Клик по ингредиенту или заказу открывает модальное окно поверх текущей страницы: маршрут перехода сохраняется в `location.state.background`, а поверх отрисованных `Routes` рендерится вторая группа маршрутов с модальным окном. При прямом переходе по URL та же информация открывается как полноценная страница.

## Глобальное состояние

Store собирается из пяти слайсов (`combineReducers`, `configureStore`) в `src/services/store.ts`:

| Слайс               | Что хранит                                                                      |
| ------------------- | ------------------------------------------------------------------------------- |
| `ingredients`       | список ингредиентов с сервера, флаг загрузки, ошибка                            |
| `burgerConstructor` | выбранная булка и список начинок/соусов с уникальными `id` для перестановки      |
| `user`              | данные пользователя, флаги `isAuthChecked` и `isAuthenticated`, статусы запросов |
| `order`             | оформленный заказ и заказ, загруженный по номеру                                 |
| `feed`              | лента заказов и история заказов пользователя: `orders`, `total`, `totalToday`     |

Запросы к серверу выполняются через `createAsyncThunk` (`fetchIngredients`, `createOrder`, `getOrderByNumber`, `fetchFeed`, `fetchUserFeed`, `loginUser`, `registerUser`, `getUser`, `updateUser`, `logoutUser`); состояния `pending` / `fulfilled` / `rejected` обрабатываются в `extraReducers`. Хуки `useDispatch` и `useSelector` типизированы в `src/services/store.ts`.

## Авторизация и защищённые маршруты

- `accessToken` хранится в cookie, `refreshToken` — в `localStorage` (утилиты в `src/utils/cookie.ts`).
- В `src/utils/burger-api.ts` реализован `fetchWithRefresh`: при ошибке `jwt expired` пара токенов обновляется через `/auth/token`, после чего исходный запрос повторяется.
- При старте приложения `App` проверяет cookie `accessToken`: если токен есть — загружает пользователя (`getUser`), иначе снимает флаг ожидания (`authChecked`).
- Компонент `ProtectedRoute` управляет доступом:
  - без флага `onlyUnAuth` — неавторизованный пользователь перенаправляется на `/login`, а исходный маршрут сохраняется в `state.from` для возврата после входа;
  - с флагом `onlyUnAuth` — авторизованный пользователь уводится со страниц входа, регистрации и восстановления пароля.
- Пока статус авторизации не проверен, отображается прелоадер.

## Тестирование

### Юнит-тесты (Jest)

Лежат рядом со слайсами в `src/services/slices/__tests__/`:

- `ingredientsSlice.test.ts` — состояния `pending`, `fulfilled`, `rejected` для `fetchIngredients` и возврат `initialState` при неизвестном экшене;
- `constructorSlice.test.ts` — редьюсеры конструктора: установка булки, добавление, удаление, перестановка ингредиентов и очистка.

```bash
npm test
```

Покрытие собирается автоматически и сохраняется в каталог `coverage/`.

### Интеграционные тесты (Playwright)

Тесты в `tests/constructor.pl.tsx` (`playwright.config.ts` подхватывает файлы `**/*.pl.tsx`) описывают реальные пользовательские сценарии:

- добавление булки и начинки в конструктор;
- работу модального окна ингредиента: открытие, закрытие по крестику и по клику на оверлей;
- оформление заказа с проверкой номера, очисткой конструктора и закрытием модального окна.

Запросы к API не выполняются по-настоящему: они подменяются ответами из HAR-файлов `tests/hars/*.har`, поэтому тесты не зависят от состояния бэкенда. Dev-сервер Playwright запускает сам (см. `webServer` в `playwright.config.ts`). Тесты выполняются в Chromium, Firefox и WebKit.

```bash
npm run test:integration
```

Перед первым запуском могут потребоваться браузеры Playwright:

```bash
npx playwright install
```
